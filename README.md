# Портфолио педагога в мессенджере MAX

Бот собирает фотографии грамот за конкурсы и удостоверений о повышении
квалификации, распознаёт документы, даёт проверить и исправить поля, сохраняет
данные в SQLite и показывает отчёт за текущий отчётный период.

Имя бота: `ideya_fiks_187_bot`

Ссылка на бота: https://max.ru/ideya_fiks_187_bot

## Сценарий

```
/start
  └─ ввод ФИО
       └─ [🏅 Добавить грамоту] [🎓 Добавить курс ПК]
            └─ «Пришлите фото документа или PDF» + [❌ Отмена]
                 └─ распознавание (OCR + Yandex LLM)
                      └─ проверка полей: «Оставить» / «Изменить» + [❌ Отмена]
                           └─ «💾 Сохранить» / «❌ Отменить»
                                └─ отчёт за текущий период + те же кнопки
```

Кнопка «❌ Отмена» доступна на каждом шаге добавления документа. При нажатии
черновик и загруженный файл удаляются, в базу ничего не записывается.

В отчёте у каждого документа есть кнопка — по нажатию бот присылает фото
документа и его данные.


## Документы

**Грамота или диплом за конкурс:** название конкурса, организатор, уровень
(Муниципальный / Региональный / Федеральный / Международный), даты проведения,
результат (победитель / призер / участник).

**Документ о повышении квалификации:** название курса, организатор, дата
выдачи, количество часов, регистрационный номер.

## Отчётные периоды

Используются два периода:

- `01.09 — 31.01`
- `01.02 — 31.08`

Бот показывает документы за тот период, который ближе к текущей дате.
Например, 08.11.2026 — это период `01.09.2026 — 31.01.2027`.

Для отчёта используется дата выдачи/проведения из поля `dates`, а не
`created_at`:

- КПК — дата выдачи;
- конкурс — дата окончания (если указан диапазон).

Если в текущем периоде документов нет, бот показывает пустой отчёт.

## Команды

- `/start` — начать работу / показать отчёт;
- `/my` — показать отчёт;
- `/cancel` — отменить незаконченный документ.

## База данных

Файл: `data/documents.sqlite3`. Работа с БД — через SQLAlchemy 2.0 ORM
(пакет `db/`). Таблицы `users` и `documents` создаются автоматически при
первом подключении к файлу БД.

```
TABLE users
    user_id             INTEGER  PRIMARY KEY
    fio                 TEXT
```

```
TABLE documents
    id                  INTEGER  PRIMARY KEY
    user_id             INTEGER  REFERENCES users(user_id) ON DELETE CASCADE
    kind                TEXT     -- конкурс или курс
    title               TEXT
    organizer           TEXT
    level               TEXT     -- только для конкурса
    dates               TEXT     -- дата выдачи КПК или даты конкурса
    result              TEXT     -- только для конкурса
    hours               INTEGER  -- только для КПК
    registration_number TEXT     -- только для КПК
    photo_path          TEXT     -- путь к файлу фото
    created_at          TEXT     -- техническое поле, в отчёте не используется
```

Состояние диалога и черновик документа хранятся в памяти процесса. В БД
попадает только документ, подтверждённый кнопкой «💾 Сохранить».

## Фото документов

Фото хранятся файлами:

```
data/photos/<user_id>/<uuid>.jpg|png
```

В `documents.photo_path` записывается относительный POSIX-путь
(`data/photos/...`), одинаково читаемый на Windows и Linux.

Поддерживаются `JPG`, `JPEG`, `PNG`, `WebP` (а также `GIF`, `BMP`, `TIFF`)
и `PDF`. Тип определяется по содержимому файла, поэтому работает и фото от
MAX без имени файла или с `Content-Type: application/octet-stream`.

- Картинка сохраняется как есть. Если она слишком большая для OCR, бот
  уменьшает только копию, отправляемую в OCR, не меняя формат (JPEG остаётся
  JPEG, PNG — PNG).
- `WebP/GIF/BMP/TIFF` сохраняются в исходном формате; для OCR из них делается
  временная копия в JPEG/PNG, потому что Yandex Vision OCR не принимает эти
  форматы.
- PDF: бот берёт текст с первой страницы и сохраняет первую страницу как PNG.
  Если текстового слоя нет, первая страница распознаётся как изображение.

## Распознавание

- Модуль: `imgToFilds.py`.
- OCR: Yandex Vision OCR (`recognizeText`).
- Извлечение полей: Yandex LLM через OpenAI-совместимый
  `POST /v1/chat/completions`.
- Для курса и конкурса используются разные промпты и JSON-схемы
  (`issue_date` для курса, `event_dates` для конкурса).
- Все ключи и модель берутся из `.env`; модуль читает файл сам, переменные
  окружения имеют приоритет.
- Для PDF сначала используется текстовый слой PyMuPDF; OCR выполняется только
  если текста нет.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

В `.env` нужно указать:

```
MAX_BOT_TOKEN=...
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
YANDEX_LLM_MODEL=yandexgpt/latest
```

`YANDEX_LLM_MODEL` необязателен: по умолчанию используется
`yandexgpt/latest`. Затем:

```bash
python bot.py
```

Для запросов к `platform-api2.max.ru` проверка TLS отключена (`verify=False`)
по требованию проекта. Для запросов к Yandex OCR и Yandex LLM используется
обычная проверка TLS.

## Запуск в Docker

В образ не попадают `data/`, `ocr/` и тесты (см. `.dockerignore`). Файл
`.env` при сборке копируется в образ, поэтому работают оба способа запуска.

1. Заполните `.env` (см. `.env.example`):

```
MAX_BOT_TOKEN=...
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
```

2. Соберите образ:

```bash
docker compose build
```

3. Запуск через `docker compose` (переменные из `env_file: .env` имеют
   приоритет над файлом внутри образа):

```bash
docker compose up -d
```

Или прямой запуск без compose:

```bash
docker run -d --name portfolio-bot --restart unless-stopped ^
  -v "%cd%\data:/app/data" portfolio-bot:latest
```

На Linux/macOS вместо `^` используйте `\`, а путь — `"$(pwd)/data:/app/data"`.

4. Логи и остановка:

```bash
docker compose logs -f
docker compose down
```

Контейнер работает с `restart: unless-stopped` и часовым поясом
`Europe/Moscow` (важно для границ отчётного периода). База и фото лежат на
хосте в `./data` и переживают пересоздание контейнера.

> ⚠️ `.env` с секретами попадает в слой образа. Не публикуйте такой образ в
> открытых реестрах. Если секреты в образе недопустимы, соберите образ без
> `.env` (оставьте только `.env.example`) и запускайте с
> `--env-file .env` или через `docker compose`.

На Linux папка `data/` должна быть доступна пользователю контейнера (uid 1000):

```bash
sudo chown -R 1000:1000 data
```

Примечание: бот использует Long Polling (`GET /updates`). По документации MAX
Long Polling подходит для разработки и тестирования; для production
рекомендуется Webhook.

## Архив проекта

Для передачи проекта целиком используйте tar-архив, в который включён `.env`:

```bash
tar -cf portfolio-bot.tar --exclude=.venv --exclude=.git --exclude=__pycache__ --exclude=data/tmp .
```

В архиве есть `Dockerfile`, `docker-compose.yml`, `.env`, исходный код и
тесты. Папки `.venv`, `.git` и кэши Python исключены.

## Структура

```
bot.py            — MAX API, диалог, отчёт, показ фото
db/               — слой БД: models.py (модели), database.py (создание и операции)
imgToFilds.py     — OCR и извлечение полей через Yandex LLM
report.py         — отчётные периоды и разбор дат
storage.py        — файлы фото, определение типа, PDF → PNG
Dockerfile        — образ для запуска бота
docker-compose.yml — запуск с томом ./data и .env
tests/            — тесты парсера, периодов, БД и сценария бота
ocr/              — отдельный тестовый OCR-проект, бот его не использует
```
